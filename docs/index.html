工作流The loop

起草、修改、导出 —— 浏览器自己跟得上 Draft, revise, export — the browser keeps up on its own

不用截图，不用复制粘贴，也不用导出再刷新。 每改一处内容，页面重新渲染，已打开的标签页随之刷新。 No screenshots, no copy-paste, no export-and-refresh. Every content change re-renders the page and the open tab reloads.

  1. 要一份简历Ask for a resume

    AI 客户端调用 resume_preview，带上内容和 resume_id，A4 页面就在你的浏览器里打开了。 The AI client calls resume_preview with the content and a resume_id, and the A4 page opens in your browser.

  2. 改一改Revise it

    之后每次调用都复用同一个 resume_id，所以你已经开着的那个标签页会原地刷新，而不是再开一个。 Every later call reuses the same resume_id, so the tab you already have refreshes in place instead of a second one opening.

  3. 导出Export it

    一次 resume_export 调用，就把最终的 PDF 或 HTML 写到你指定的路径 —— 内容自上次导出后有变化时会自动重新渲染。 One resume_export call writes the final PDF or HTML to the path you name — re-rendered automatically whenever the content changed since the last export.

工作原理How it works

一个本地渲染闭环，四个环节 A local render loop, four moving parts

服务很小，行为可预期。下面就是从你提出请求到屏幕出页面之间发生的事。 The server is small and predictable. Here is exactly what happens between your request and the page on screen.

  1. AI 客户端调用工具The AI client calls a tool

    当你要一份简历时，AI 客户端调用 resume_preview，带上内容和标识这次会话的 resume_id。 When you ask for a resume, the AI client calls resume_preview with the content and a resume_id that names the session.

  2. 渲染出页面It renders the page

    服务把内容写进工作文件，再填充 HTML 模板，每个值都做转义，所以页面始终是纯文本。 The server writes the content to a working file and fills the HTML template, escaping every value so the page stays plain text.

  3. 在本地提供这个简历 It serves the resume locally

    一个小型本地服务把它托管在 http://localhost:3737/resume/<slug>，并在第一次时替你打开浏览器。 A small local server hosts the result at http://localhost:3737/resume/<slug> and opens it in your browser the first time.

  4. 通过 WebSocket 实时刷新 It reloads live over WebSocket

    之后每次用同一个 resume_id 调用，都会重新渲染文件并推送一次刷新。绿点表示已连接，红点表示正在重连。 Every later call with the same resume_id re-renders the file and pushes a reload down a WebSocket. A green dot means the tab is connected; red means it is reconnecting.

功能特性Features

为反复打磨简历而做，而不是为反复导出而做 Built for iterating on a resume, not re-exporting it

实时刷新Live reload

内容一改，浏览器自动刷新，状态圆点显示 WebSocket 连接情况。 The browser refreshes automatically as the content changes, with a status dot showing the WebSocket connection.

A4 版式A4 layout

你在浏览器里审阅的那一页，就是 PDF 打印出来的那一页 —— 不需要再对一遍打印样式。 The page you review in the browser is the page the PDF prints — no separate print stylesheet to reconcile.

PDF 与 HTML 导出PDF and HTML export

可直接打印的 PDF，或可以打开编辑的独立 HTML 文档。文件扩展名必须与请求的格式一致。 A print-ready PDF, or a standalone HTML document you can open and edit. The file extension has to match the format you ask for.

始终是纯文本Plain text, always

内容里的每个值都转义后按文本打印。HTML 标签和脚本永远不会被解释 —— 这是产品最大的 XSS 面，它会一直关着。 Every value in the content is escaped and printed as text. HTML tags and scripts are never interpreted — the largest XSS surface stays closed.

分节模型Section model

只有姓名是必填的。没写的板块会从页面上省略，顺序是固定的：自我评价 → 工作经历 → 项目经历 → 教育经历 → 专业技能 → 其他。 Only the name is required. Sections you leave out are omitted from the page, and the order is fixed: Summary → Experience → Projects → Education → Skills → Extras — in Chinese when the resume's own language says so.

两套彼此独立的语言 Two independent languages

页面框架跟随浏览器语言；简历自身的语言按份设置，决定分节标题和导出的文档 —— 所以导出的 PDF 永远不取决于谁打开它。 The page chrome follows the browser's language; the resume's own language is set per resume and decides the section headings and the exported document — so an exported PDF never depends on who opened it.

多份简历Multiple resumes

每份简历给它自己的 resume_id，同时推进好几份 —— 比如每个目标岗位一份。 Give each resume its own resume_id and work on several at once — one per job you are applying to, for example.

持久化的工作文件 Persistent working files

简历存放在 ~/.config/resume-preview/resumes，跨会话也不丢。 Resumes are kept under ~/.config/resume-preview/resumes, so they survive between sessions.

独立简历库Standalone resume library

运行 resume-preview --serve 打开浏览器简历库，列出所有已存简历 —— 不需要 agent。可以按 id 搜索、看到每份简历的最后更新时间，也能删除不再需要的。 Run resume-preview --serve to open a browser library of every stored resume — no agent required. Search by id, see when each one was last updated, delete the ones you no longer need.

审阅工具Review tools

直接在预览页里缩放、平移、导出。状态圆点显示实时连接，旁边还有"最后更新"的时间戳。 Zoom, pan and export straight from the preview page. A status dot shows the live connection, and a stamp tells you when the page last changed.

内置简历技能Built-in resume skill

Claude Code 插件自带一个技能，装着内容模型和"预览—迭代—导出"的工作流，出来的简历格式总是对的。 The Claude Code plugin ships a skill with the content model and the preview-iterate-export workflow, so resumes come out well-formed.

常见问题FAQ

值得回答的几个问题 Questions worth answering

支持哪些客户端？Which clients are supported?

它是为 Claude Code 做的，插件还会一并装上简历技能。因为它讲的是 Model Context Protocol，所以任何 MCP 客户端都能用 —— Cursor、Codex、Windsurf、Cline、Gemini CLI 都在内 —— 用标准的命令配置即可。 It is built for Claude Code, where the plugin also installs a resume skill. Because it speaks the Model Context Protocol, it works with any MCP client — Cursor, Codex, Windsurf, Cline, and Gemini CLI included — using the standard command configuration.

简历能导出成哪些格式？Which formats can a resume be exported to?

pdf 和 html。PDF 是无头 Chromium 打印出的真实 A4 页面；HTML 是可以打开编辑的独立文档。文件扩展名必须与请求的格式一致。 pdf and html. The PDF is a real A4 page printed by headless Chromium; the HTML is a standalone document you can open and edit in a browser. The file extension has to match the requested format.

导出 PDF 需要什么额外条件吗？Does exporting to PDF need anything special?

只有当文档里出现中文时才需要 —— 机器上装有中文字体，否则中文字符会变成空心方块。导出失败并给出明确报错，而不是悄悄写出一个坏文件。 locale 为 zh-CN 的简历一律按「需要中文字体」处理（它的分节标题本身就是中文）； locale 为 en 的纯英文简历在没有中文字体的机器上也能正常导出。 Only when the document actually contains Chinese — the machine needs a Chinese font installed, otherwise the Chinese characters would come out as empty boxes. The export fails with a clear message instead of quietly writing a broken file. A resume with locale set to zh-CN always counts as Chinese (its section headings are Chinese); a resume written entirely in English exports fine on a machine without a Chinese font.

我的简历存放在哪里？Where are my resumes stored?

简历存放在 ~/.config/resume-preview/resumes/<slug>/ 下，跨会话也不丢；日志在 ~/.config/resume-preview/logs。 resume_export 工具把产物写到你指定的任意路径，比如 ./docs/resume.pdf。 Resumes are kept under ~/.config/resume-preview/resumes/<slug>/ so they persist between sessions, and logs live under ~/.config/resume-preview/logs. The resume_export tool writes the artifact to any path you choose, such as ./docs/resume.pdf.

支持哪些语言？Which languages are supported?

两种，而且彼此独立。页面框架跟随请求 —— ?lang=en 优先，其次是浏览器的 Accept-Language，最后是 zh-CN。简历本身跟随你传给 resume_preview 的 locale，它与简历一起存储，决定分节标题和导出的文档。导出永远不依赖浏览器，所以同一份简历每次导出都一样。 Two, and they are independent of each other. The page chrome follows the request — ?lang=en wins, then the browser's Accept-Language, then zh-CN. The resume itself follows the locale you pass to resume_preview, which is stored with the resume and decides the section headings and the exported document. The export never depends on the browser, so the same resume always exports the same way.

用哪些端口？What ports does it use?

本地预览服务使用 3737–3747 端口，自动挑第一个空闲的。它只绑定 127.0.0.1，且没有鉴权 —— 简历含个人数据，绝不要暴露到局域网。 The local preview server uses ports 3737–3747 and automatically picks the first one that is free. It binds to 127.0.0.1 only and has no authentication — a resume holds personal data, so never expose it to your LAN.

能同时做多份简历吗？Can I work on several resumes at once?

可以。给每份一个自己的 resume_id，比如 company-a 或 company-b，每份都有各自独立的实时 URL。修改同一份简历时复用同一个 resume_id，刷新的是你已经开着的那个标签页。 Yes. Give each one its own resume_id, such as company-a or company-b, and each gets its own live URL that reloads independently. Reuse the same resume_id to revise a resume in the tab you already have open.

内容里可以放 HTML 吗？Can the content contain HTML?

不可以，而且是刻意的。每个值都转义后按文本打印，标记会原样显示，不会被解释。写纯文本就好。 No, and deliberately so. Every value is escaped and printed as text, so markup shows up literally instead of being interpreted. Write plain text.

免费吗？Is it free?

免费。resume-preview 是 MIT 许可证下的开源项目。 Yes. resume-preview is open source under the MIT license.
